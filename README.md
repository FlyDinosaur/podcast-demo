# 简易“播客节目列表”页面

## 完成的功能
1. 节目列表显示，每个节目item包括封面图、标题、作者、时长、播放状态以及播放按钮；使用`ScrollView`支持列表上下滑动
2. 支持从本地文件中读取json数据，`/Poadcast/data/Audio/`目录下保存播客音频，`/Poadcast/data/Image/`目录下保存播客的封面，`/Poadcast/data/Info/`文件夹下保存当前播客信息。示例json文件格式如下：
```json
{
    "id": "8f3c4b7a-2d91-4e6a-9f35-1c0a7d5e2b11", // UUID
    "title": "清晨咖啡时光", // 标题
    "host": "主播 小林", // 作者
    "duration": "00:06", // 音频时长
    "coverImageURL": "/data/Image/Image01.png", // 封面图路径
    "audioURL": "/data/Audio/test01.wav" // 音频路径
  }
```
3. 播放状态切换，点击任意节目条目时，该条目背景颜色及边框颜色将变为深橘色，表示选中该条目，并开始播放音频。并且对应条目的Image图标进行更改为`pause.circle.fill`，当再次点击播放图标后，音频停止播放，并将Image图标改为`play.circle.fill`系统图标。
4. 实现了音频播放功能
5. 制作了一个底部悬浮弹窗，用于显示当前播放节目的基础信息及播放操作。当用户点击任意节目后，将会弹出一个悬浮小型播放器弹窗，主要为封面图、标题、主播名以及播放按钮控制。背景使用毛玻璃质感，用户可以将悬浮窗向下滑动，使其隐藏，当用户点击任意其他节目后，悬浮窗将再次出现。
6. 适配了深色模式，用户切换显示模式后将动态切换到深色模式。
7. 制作了Tab切换页面，适配iOS18液态玻璃设计，用户可以点击或滑动底部的页面切换器跳转到对应的页面，这里模拟有`发现`，`我的`两个其他页面（占位），点击后即可跳转到对应页面，同时第6条的迷你播放器不会消失，仿照Apple Music的设计模式，保留迷你播放器。
8. 制作了节目列表的下拉刷新功能。
9. 项目同步在github仓库中，项目地址：[https://github.com/FlyDinosaur/podcast-demo]

## 技术选型及设计思路
1. 技术上UI框架选择SwiftUI，项目架构采用MVVC架构，能够将模块之间尽可能分离。音频播放选择AVFoundation里的AVPlayer进行播放。状态管理采用的是系统的Observation。
2. 实现思路：用SwiftUI+MVVC把本地JSON、封面图和音频资源解析成统一的播放列表状态，由共享 PlaybackController管理单例播放会话，再同步驱动列表页和底部 mini 播放器的展示与交互。

## 运行说明
无特殊环境需要配置。data文件中保存了这个Demo所需要演示的所有文件，只需要选择iPhone系列模拟器直接运行即可。

## 遇到的主要困难和解决方法
基本没有遇到很大的困难，但是基于LLM生成的第一版UI有比较大的问题，例如每个播客列表中的item，`.padding`与`.overlay`之间的顺序不同，导致最后渲染中背景只包裹了文字，没有包裹整个框。解决方法为将`.padding`，`.background`，`.overlay`重新调整，解决渲染问题。此外在项目开始，URL读取方法设计的有部分问题，导致没有正确读取音频文件及封面图。解决方法为改写bundle查找路径。

## 使用的AI Coding Agent方法
1. 主要使用的Coding Agent为`Codex`，模型使用为`GPT-5.4(OpenAI官方API)`，智力程度`Medium`，配合使用`speckit`插件。
2. 项目采用git管理工具，要求代码提交commit必须符合`<type>(<scope>): <subject>`格式，保证修改的可读性。并编写为SKILL，在使用coding agent提交commit时也能够遵守commit规范。
3. `speckit`主要采用功能编写阶段，采用规范驱动开发方法。用于确定软件生命周期中一个功能的设计原则（speckit.constitution）、需求分析(speckit.specify)、实现方案(speckit.plan)等。对于设计准则，采用的是项目全局采用MVVC架构、严格模块分离、每个功能函数必须有详细英文注释，包括函数名、函数形参、函数功能以及返回值说明，保证项目代码的可读性。在需求分析阶段，我详细说明了这个页面需要有什么功能及描述。完成后我使用speckit.plan模式规划实现方案，并用speckit.clarify说明我项目中实现的可能冲突点，并一一澄清，解决冲突描述。之后使用speckit.task生成实现步骤，及用户故事，保证功能符合预期要求。最后采用speckit.implement实现代码全部功能。并最后人工检查冲突及不合理之处，手动修改。具体可以查看项目中的specs文件。
